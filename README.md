# In Sea — 인천 낚시 관광 정보 앱 (백엔드)

인천의 낚시터·식당·숙소를 지도에서 찾고, 그날의 날씨·조석과 잡아도 되는 어종(금어기)까지 한 화면에서 보는 앱.
2025 관광데이터 활용 공모전(한국관광공사) 출품작으로 원스토어에 출시했다.

> 팀 CheckMate(4인) 백엔드 저장소의 **본인 담당 모듈만** 공개한 쇼케이스입니다. 전체 저장소는 팀 소유라 비공개이며, 이 저장소만으로는 빌드되지 않습니다.
> 팀 전체 코드 12,600줄 중 아래 5개 모듈 약 8,700줄을 맡았습니다. 코드·데이터의 재배포 및 상업적 이용은 허용하지 않습니다.

## 팀과 역할

| 역할 | 담당 |

| 프론트엔드 (팀원 2) | Android 앱 |

## 이 저장소의 구성

```
src/main/java/checkmate/insea/
├── review/      리뷰 작성·수정·소프트 삭제·좋아요, 장소별 리뷰·종합 평점
├── user/        장소 즐겨찾기, 닉네임·이메일·비밀번호 변경, 프로필 이미지, 회원 탈퇴, 전역 예외 처리
├── fishbio/     물고기 백과사전 — 국립해양생물자원관 API 동기화, 키워드·학명·국명·과·서식지 조회
├── fish_info/   금어기 조회·검색·추천, (삭제된) 엑셀 기반 어종 정보·분류 아이콘
└── image/       Cloudinary 업로드·삭제·썸네일
src/main/resources/templates/
└── fishing-ban-data-2025.json   국립수산과학원 금어기 규정(2025.01 시행)을 직접 JSON으로 변환한 데이터
```

전체 앱 구조(비공개 부분 포함): `map`(TourAPI·카카오맵) · `weather`(기상청·바다누리) · `fishing_tip` · `config`(Security·JWT)

## 기술 스택

Spring Boot · Spring Data JPA · PostgreSQL(PostGIS) · Spring Security + JWT · Cloudinary · Railway(배포) · Caffeine 캐시

## 설계에서 결정한 것들

### 리뷰 — "장소당 1인 1리뷰"를 어떻게 지킬까

DB에 UNIQUE(place, user)를 걸면 삭제 후 다시 쓰기가 막히고, 빼면 중복이 생긴다. 소프트 삭제(`status = DELETED`)로 두고, 같은 장소에 다시 쓰면 삭제된 행을 되살려 덮어쓴다. 좋아요·신고 수는 0으로 초기화하고, 장소 평점 통계에서 옛 평점을 빼고 새 평점을 더한다. (`review/service/ReviewService.createReview`)

### 장소 평점 — 매번 AVG 쿼리를 날리지 않기

지도 목록에서 장소 수십 개의 평점을 한 번에 보여줘야 한다. `Place`에 1~5점 개수와 평균을 저장해 두고 리뷰 작성·수정·삭제 때 증감만 한다. 읽기 비용을 줄이는 대신 쓰기 경로에서 통계를 항상 같이 갱신해야 한다.

### 어종 데이터 — 엑셀을 버리고 API로

처음엔 국립수산과학원 생물종 엑셀(822종)을 파싱했는데, 통계를 뽑아 보니 771종이 한 과(科)로 묶이는 등 분류 정보가 깨져 있었다. 어종 정보·분류 아이콘 기능을 삭제하고 국립해양생물자원관 API를 100건씩 페이징으로 전부 받아 저장하는 `fishbio` 모듈로 다시 만들었다. 응답이 ISO-8859-1로 와서 한글이 깨지는 문제는 바이트를 UTF-8로 재해석해 해결. (`fish_info`에 삭제된 코드도 남겨 두었다 — 왜 버렸는지가 결정의 일부라서)

### 금어기 — 규정을 데이터로

국립수산과학원 공개 규정(2025.01 시행)을 어종·기간·지역·금지 유형(기간/크기)으로 정리해 JSON 리소스로 넣고, 서버 시작 시 로드·수정 후 리로드 엔드포인트를 둔다. 그 위에 날짜·지역별 포획 가능 어종, 어종별 연간 스케줄, 어종명 자동완성, 기간별 추천 점수, 해제 예정 어종 조회를 올렸다.

### 이미지 — 썸네일을 서버에서 만들지 않기

Cloudinary에 올리고, 썸네일은 서버 API 대신 URL 변환(`w_150,h_150,c_fill,g_face`)으로 해결했다. 프로필 교체 시 기존 이미지는 자동 삭제.

## 알고 있는 한계

- 백과사전 동기화가 단일 트랜잭션의 15분짜리 동기 루프다. 팀원이 비동기로 바꾼 커밋이 있었는데 마지막 머지에서 덮여 사라졌다. `@Async` + 페이지 단위 트랜잭션으로 고쳐야 한다.
- 테스트가 DB 연결 확인용 몇 개뿐이다. 리뷰 재활용처럼 상태 전이가 있는 로직부터 붙여야 한다.
- 설정 파일에 API 키가 커밋된 채 개발했다. 출시 1년 뒤 공개하려고 전체 이력을 다시 썼다. 첫 커밋부터 환경변수로.
